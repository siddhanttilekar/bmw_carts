**1. Modules implemented**
- **Decision assistant:** answers 8 kinds of question (why this priority, why this agent's score, supporting evidence, comparison, what's missing, what-if, challenge, reliability). Each goes to a calculation over saved data; unclear free text gets suggested questions instead of a guess.
- **Grounding:** labels every statement FACT, ASSESSMENT, ASSUMPTION, LIMITATION or SIMULATION. It checks every evidence ID against the database, ties each answer to one saved run, and shows a notice when that run is out of date.
- **Agent chat:** explains an agent from its configuration saved with the run, so custom agents work the same way.
- **Debate:** four rounds built from saved scores. Agents abstain when data is missing, and no winner is declared if either requirement is incomplete.
- **What-if simulator** and **scenario comparison**.
- **Challenges:** a challenge records the dispute and its review but never changes a score.
- **Reports:** Excel, CSV and PDF.
- **Optional LLM rewording:** disabled.

The page has screens A–E and its own section in the sidebar navigation.

**2. Database changes**
- **8 new tables:** conversations and messages, debates, challenges and their audit events, scenarios, comparisons, and a report export log.
- **One new column:** runs now record which requirement version they scored, so comparisons can flag a requirement edited between runs. Older runs leave it empty.

Nothing existing was changed or removed.

**3. Offline assistant.** It works without credentials and answers only from saved runs and records. Each answer carries the label "Evidence-based explanation — not AI-generated", and the history stores evidence IDs rather than customer comment text.

**4. LLM mode:** disabled. Enabling it would need explicit authorisation, an Anthropic API key (a ChatGPT subscription doesn't provide one), a cost estimate you've seen, and your confirmation. **How it works**
- **Extraction (versioned `observe-v1`):** each G60 comment can yield several observations: complaint, improvement request, positive, neutral or unclear. Each quote must appear word for word in the original comment, or that observation is rejected and logged. Results are cached and never overwritten.
- **Evidence selection (`select-v1`):** each requirement gets lists of distinct comment IDs for complaints, requests, positives, counter-evidence and uncertain matches. Combined demand counts a comment with both a complaint and a request once. Human accept/reject/uncertain reviews always override AI matches.
- **Scoring (`log-feedback-v1`):** three new AI-analysis methods (complaint frequency, request frequency, combined demand) use score = 100·ln(1+n)/ln(1+4000). Python counts and calculates; the model never chooses a number. An agent is UNSCORED unless every direct comment for that requirement has been extracted.
- **Snapshots:** each run freezes the evidence it used, so a saved run never changes. "Reanalyze With New Evidence" creates a new run plus a comparison.
- **Screens:**
  - DISCOVER shows extraction status, the budget and the sample run.
  - DEFINE has evidence selection and the review workflow.
  - PRIORITIZE shows the calculation behind each score and the seven-field agent builder with file uploads.
  - DECIDE adds an evidence-aware debate in which agents abstain when evidence is missing, history/reanalysis, human approval and export.
