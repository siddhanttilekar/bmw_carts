KEY RULES THE USER SET (keep following them)
--------------------------------------------
Data integrity
  - Never fabricate data, IDs or statistics.
  - Missing values stay NULL.
  - Preserve original BMW VFC classifications.

Counting and labelling
  - Count comments with COUNT(DISTINCT feedback ID); classification rows are not customers.
  - Feedback Type is NOT sentiment: no positive/negative percentages.
  - G60 analysis excludes F70 and G70.
  - G60/G68 sales are combined; never present them as G60-only.

Evidence
  - Keep internal and public evidence separate.
  - Evidence tiers: DIRECT (internal BMW feedback), SUPPORTING (public BMW feedback and studies),
    CONTEXTUAL (competitors and equipment).
  - Competitor data is never proof about BMW customers.
  - Template insights must never be labelled as AI-generated.

LLM use
  - No external or paid LLM calls unless explicitly authorised:
    PRODUCTMIND_ALLOW_EXTERNAL_LLM=true, an API key, a cost estimate shown, and user confirmation.
  - No automatic model fallback (PRODUCTMIND_LLM_FALLBACKS defaults to off).
  - Default model when authorised: claude-opus-5-5.

Requirements
  - Requirements must trace to real evidence IDs.
  - No invented BMW specifications; acceptance targets are "proposed - requires validation".
  - No assumed launch year: the target is "next-generation BMW 5 Series".
  - Human review is required; there is no auto-approval and a four-eyes rule applies.

Scope
  - Each part stops at its stated scope.
